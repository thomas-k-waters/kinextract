kinextract_lite: what it does, and why it's built this way

A from-scratch line-of-sight velocity distribution (LOSVD) extractor for galaxy spectroscopy, built for black-hole-mass work via stellar dynamics. This page walks through every live mechanism in the package, why each one exists, and where the ongoing validation work currently stands — including the negative results, not just the wins. For the precise mathematical form (the forward model equation, the objective, the noise model), see the companion Forward Model Reference; this page is about the software and the methodology story around it.

01Why not just fit a Gauss-Hermite expansion?

The standard shortcut in this field is to skip the LOSVD entirely and fit four numbers instead — V, σ, h3, h4 — via a truncated Gauss-Hermite series. It's fast, well-understood, and every downstream Schwarzschild/orbit-superposition code speaks that language. It is also a fixed-shape model: at most a Gaussian core plus one antisymmetric and one symmetric correction term. Real LOSVDs routinely have more structure than that — a rotating disk component sitting at its own velocity, a pressure-supported body, and an extended high-velocity wing from orbital anisotropy are all superposed in the same spectrum.

This is the entire reason kinextract_lite fits the LOSVD itself as a free-form curve rather than a 4-parameter shape. The parametric route isn't wrong so much as it silently assumes the truth already looks like a Gaussian-with-corrections — an assumption real galaxies routinely break (disks, counter-rotating cores, radial orbital anisotropy in the outskirts, tidal debris). A non-parametric fit can represent multi-component structure without going negative, if it's built to be structurally incapable of going negative in the first place — the very next section.

02LOSVD representation: a structurally-positive log-spline

The LOSVD b(v) is represented as a cubic B-spline in log-space:

b(v) = exp( Σj cj · Bj(v) )
  • B_j(v) — the j-th cubic B-spline basis function on the velocity grid
  • c_j — the fitted spline coefficients (what the optimizer actually solves for)
  • v — line-of-sight velocity, on a grid spanning roughly V ± 7σ

Positivity is structural, not enforced. There is no boundary at b = 0 for the optimizer to run into, and no post-hoc clipping step that would silently make the reported curve the answer to a slightly different problem than the one actually solved. The continuum spline (§7) and the LSF-matching step both reuse this same exp-link idea.

The number of spline knots scales with how wide the velocity grid is (knot_spacing_kms, default ~95 km/s/knot) rather than being fixed — a fixed knot count too coarse for the grid width was measured to produce 47-58% shape residual; the auto-scaled default keeps this comfortably under 5%.

03Noise model & whitening built this session

Every fit in this package works on whitened data — the design matrix and observed flux divided by the noise model, so an ordinary sum-of-squares becomes the statistically correct weighted chi-squared. Until this session, the noise model was implicitly "every pixel is independent" (plain division by the per-pixel error). Two independent diagnostics on real MUSE star spectra found that's measurably wrong: genuine lag-1 pixel-to-pixel noise correlation of roughly 0.1-0.5, which survives even after continuum-detrending removes the (much larger) apparent correlation caused by unmodeled template mismatch.

A new module (noise_model.py) makes the covariance explicit and pluggable — a stationary AR(1) model, Σ_ij = err_i·err_j·ρ^|i−j| — with proper GLS whitening (A_w = L⁻¹A, y_w = L⁻¹y via the Cholesky factor Σ = LLᵀ). Critically, ρ = 0 reproduces the old plain-division convention bit-for-bit (verified directly), and no changes were needed anywhere in the actual fitting engines — they only ever consumed whitened inputs, so the whole upgrade lives in how those inputs get built.

calibrated, not yet defaulted Measured ρ ≈ 0.09–0.49 across real stars (mean ≈ 0.21, median ≈ 0.13) — real, star-to-star scatter, not measurement noise. Recommended as an informed starting point for real-data work; the package default stays ρ = 0.0 until there's a principled per-target estimation procedure, not silently changed underneath existing users.

04The fitting objective: penalized likelihood

Coefficients are found by minimizing whitened data chi-squared plus a curvature penalty (a P-spline, Eilers & Marx 1996) — this whole family of methods (Saha & Williams 1994 → Gebhardt et al. 2000b → Pinkney et al. 2003) is usually called Maximum Penalized Likelihood (MPL):

minimizec ½‖Aw·b − yw‖² + ½·λ·‖D₂·c‖²
  • A_w — whitened design matrix: each column a stellar template Doppler-shifted to one velocity-grid point, whitened per §3
  • y_w — whitened observed flux
  • D₂ — a second-difference operator on the spline coefficients (penalizes curvature, not raw amplitude), scaled by real velocity spacing so a given λ means the same thing on any grid width
  • λ ("lam") — regularization strength; default 2.0, fixed by default, adaptive alternative now validated (§8)

Optimization is exact-gradient L-BFGS-B (JAX autodiff through the exp link) — deterministic given a starting point, which is exactly why the starting point needs care (next section).

05Multi-start: the landscape isn't convex

Because b = exp(spline) is a nonlinear reparameterization, the objective in coefficient space is not convex. A single starting point — even a good, data-driven one — lands in a real, meaningfully-suboptimal local minimum in roughly 1 in 150 noisy fits, with no other visible warning sign (reported success=True, no error). The default pool of three starts (a closed-form ridge estimate of b, plus two flat starts at different scales) catches this at the cost of a few hundred extra milliseconds per fit — cheap relative to a silently wrong LOSVD.

06Multi-template fitting: one engine, any template count

Real spectra are a mixture of stellar populations, not one template. Rather than a separate code path for "one template" vs. "many," there is a single alternating-minimization engine parameterized by a template stack of shape (n_templates, n_pixels, n_velocity_bins) — n_templates=1 is just the one-column case of the same problem.

A_eff(w) = Σk wk · A_stack[k]

Each iteration: fix the mixture weights w and solve for b (§4-5 above, against A_eff(w)); then fix b and solve for w via non-negative least squares (NNLS — convex, exact, no local-minimum risk on this half of the problem). Repeat until the joint objective stops improving.

non-identifiability to know about The model is invariant under (w, b) → (c·w, b/c) for any c > 0 — the absolute scale of w/b the fit lands on is arbitrary. Always read off mixture fractions as w / w.sum(), never raw w.

07Continuum co-fitting promoted to standard this session

Real templates never match a real galaxy's continuum shape perfectly (flux calibration, dust, population differences). Left uncorrected, that broadband mismatch has nowhere to go except the LOSVD itself — it gets misattributed as kinematic structure rather than showing up as residual. A shared, structurally-positive multiplicative continuum (same exp(spline) idea as §2, over wavelength instead of velocity) is now co-fit as a third alternating block: fix (b, w), solve the continuum; fix (b, C), solve w; fix (w, C), solve b. This was previously a separate, parallel-maintained code path, on hold pending the noise-model work above; this session merged it into the same alternation driver as the plain 2-block fit (continuum_knots=None reproduces the old behavior exactly) and promoted it to a standard, opt-in FitConfig field.

a flag that looks scarier than it is The continuum sub-fit's own optimizer frequently reports success=False ("ABNORMAL" L-BFGS-B termination). An earlier hypothesis blamed the LOSVD sub-fit misbehaving inside the continuum-alternation context specifically — traced step-by-step this session and found wrong: the LOSVD sub-fit succeeds in every iteration checked; the flag comes from the continuum block's own optimizer. Further check: every multi-start candidate converges to the same objective value regardless of the flag, and a direct 60+ fit bias comparison found no statistically significant difference between flagged-success and flagged-failure fits (+21.45 vs. +20.78 km/s mean sigma-bias). Conclusion: the flag is a scipy line-search technicality on an already-well-converged, low-dimensional problem, not a real accuracy signal — fixed the reporting (a separate bug meant the wrong sub-block's message was shown when this happened) and corrected the documentation, but did not build a workaround for the flag itself, since it doesn't appear to indicate anything wrong.

08Fixed vs. adaptive regularization evidence validated, promotion decision pending

The fixed λ = 2.0 default (§4) is not adaptive to signal-to-noise or velocity dispersion — the ablation ladder (§10) found this is a real, sometimes-dominant bias source at low σ. This session validated a data-driven alternative: generalized-AIC regularization selection (Lipka & Thomas 2021; Thomas & Lipka 2022) — pick λ from a grid to minimize chi² + w_m·m_eff, where m_eff is the fit's own effective degrees of freedom at that λ (a bootstrap estimator, expensive; and a closed-form local approximation, select_lambda_aic_local, cheap — no bootstrap refitting).

The closed-form version had never been tested against a mock with genuine non-Gaussian wings (h4=0.15) before this session — only the expensive bootstrap version had. Closing that gap was the concrete blocking requirement, and the result was positive:

Adaptive regularization beats the fixed default on σ-bias at every tested σ, with the gap widening at high σ — roughly halving the bias at σ=300. This is a genuine, meaningful result, not a marginal one, given how central correct regularization is to the whole project.

firming up before committing running This result is n=6 replicates/cell — directionally strong, but this project has been burned before by declaring something fixed on a small sample (see §11's methodology trap, and the original wing-coverage catastrophe). A larger run (25 reps/cell, both h4=0 and h4=0.15 truths) is in progress to confirm this generalizes before adaptive regularization is promoted to default or shipped as a fully-supported option.

09Summarizing the recovered curve as (V, σ, h3, h4)

The recovered b(v) curve is the real scientific product — but it still needs to be reported as comparable numbers. V/σ come from a direct moment of the recovered curve, not a second model fit:

V = Σ v·b(v)·τ(v) / Σ b(v)·τ(v) σ = sqrt[ Σ (v−V)²·b(v)·τ(v) / Σ b(v)·τ(v) ]

where τ(v) is a smooth logistic taper that downweights the noise-dominated far wings — a hard cutoff is measurably worse for skewed LOSVDs specifically (asymmetric about the true center for any skewed density, biasing the windowed moment toward the heavy tail). Benchmarked directly against a full parametric Gauss-Hermite fit across this package's validation grid, the tapered direct moment wins on both V (std 2.5 vs. 8.7 km/s) and σ (std 2.9 vs. 7.4 km/s).

h3/h4 still come from a Gauss-Hermite fit — but with V/σ held fixed at the values above rather than jointly optimized, which loses nothing relative to a full 5-parameter joint fit while removing any V/σ ↔ h3/h4 coupling from the estimate.

10Uncertainty: parametric bootstrap

Fit once for the point estimate, then refit n_boot times against that same point estimate's own best-fit model spectrum plus freshly simulated noise — every replicate goes through the entire pipeline, multi-start included, so a replicate landing in a worse basin shows up as genuine spread rather than being invisible to the uncertainty estimate. The full ensemble (b_boot/w_boot, not just summary statistics) is the recommended product for anything propagating uncertainty forward, e.g. into downstream orbit-superposition modeling.

The noise injected into each bootstrap replicate needed reconsidering once §3's covariance model arrived. The resolution (confirmed by direct numerical test, not assumed): if the inputs are properly pre-whitened against the true covariance, the whitened residuals are already i.i.d. N(0,1) regardless of ρ's value — GLS whitening removes correlation rather than just rescaling it. So plain noise injection is already correct in the mainline case; an optional L parameter exists only for deliberately testing an assumed-vs-true covariance mismatch, which is the realistic case since ρ is always only an estimate.

11Regularization bias, and the correction on top of it correction shipped, negativity bug fixed

The curvature penalty in §4 that keeps the LOSVD fit well-posed also biases it — a documented property of the whole MPL lineage (Pinkney et al. 2003), not a bug. A synthetic-calibrated correction (Pinkney's own prescription) is wired into bootstrap_losvd/compute_losvd_moments by default, as new _corrected-suffixed fields — no existing key's meaning changes. It corrects σ and h4 only (V bias was found consistent with pure noise; nonzero-truth h3 bias has no calibration data yet).

a real bug, found by inspecting a sandbox notebook The correction reconstructs a Gauss-Hermite curve from the corrected (σ, h4) for reporting/comparison purposes. That reconstruction can go negative near the core edges — a known property of truncated Gauss-Hermite curves at large |h4| in general, but the correction's additive h4 shift can push a curve that would otherwise have stayed positive into that regime. Found in three call sites (correct_losvd, compute_losvd_moments, bootstrap_losvd) and fixed by clipping non-negative — matching the convention already used everywhere else in the package a Gauss-Hermite curve is treated as a final density. Three regression tests (using a deliberately extreme synthetic calibration to force the failure deterministically) confirm the fix.
a real methodology trap, worth remembering The first two calibration attempts were checked against the legacy Fortran pipeline's own output (pallmc.out) and looked like they were making things worse. They weren't — the legacy pipeline carries its own real biases, so "agrees with legacy" was never a valid correctness test. Switching to known synthetic truth as the scoreboard reversed the conclusion entirely. See §12.

14The calibration/adaptive-λ coupling decision made, build pending

Every existing bias-correction calibration table (§11-12) was built by fitting at a fixed λ=2.0. §8's adaptive selection picks wildly different λ depending on σ (roughly 0.5-1.0 at σ=50, up to 16-36 at σ=300) — meaning the two mechanisms are not independent. Using adaptive regularization together with the existing calibration table is inconsistent: the correction's validity was only ever established at λ=2.0, and adaptive selection deviates furthest from that exactly where correction matters most (high σ).

Decision: given how central correct regularization is to this project's actual scientific goal, the calibration will be extended to a real second axis — m_eff (effective degrees of freedom, already computed as part of adaptive selection) rather than raw λ, since m_eff already absorbs velocity-grid scaling that makes a given λ mean different things on different grids. The fixed-λ path stays fully supported and well-calibrated too, for users who want deterministic behavior — this is an addition, not a replacement. Sequencing: firm up §8's evidence first (running now), then build the extended calibration.

15E-MILES templates viable with caveats, not yet integrated

The 33-star real MUSE library used everywhere above has zero template/instrument LSF mismatch by construction (it's real MUSE data), but limited stellar-population coverage. E-MILES SSP models (LSF-matched to MUSE via a Gaussian quadrature-difference convolution) would give much broader age/metallicity coverage — and are a hard requirement for instruments without their own dedicated library (e.g. HST STIS).

The first mismatch test (fitting a mock built from real MUSE stars, using an E-MILES template set, with continuum-cofitting off) showed catastrophic bias — sigma-bias up to +209%, velocity-bias up to −336 km/s in a wide (1400 Å) window. Rerunning with continuum-cofitting on (§7, not available when this test was first built) resolved most, but not all, of it:

windowσ regimeE-MILES vs. MUSE library
narrow (CaT, 400 Å)low σ (30-80)worse (+58% to +207% vs. +32-77%)
narrow (CaT, 400 Å)high σ (140-300)better (+7-22% vs. +21-61%)
wide (1400 Å)high σ (220-300)catastrophically worse either direction

A fairer, reversed test (mock built from an E-MILES population mixture, checking how well the MUSE library recovers that) confirms the narrow-window mismatch cost is real but modest and bidirectional — not the catastrophic, one-sided story the first test alone would suggest. Fit-window width, not which template library, is the dominant risk factor: a wide window punishes whichever library is mismatched, severely; the already-validated narrow CaT window stays safe either way.

status Viable, but only with continuum-cofitting on and confined to the validated narrow window — not a "wire it in" situation yet. Investigating this also surfaced the continuum-block ABNORMAL-flag question in §7, which is now understood and not a blocker.

16Variable projection (VARPRO) tried, not adopted

A classical reformulation (Golub & Pereyra 1973) of the alternating scheme in §6: instead of alternating between solving w and b, profile w out entirely (fresh NNLS at every trial b) and hand a single outer optimizer the reduced objective directly. A tiny smoke test (3 reps) looked excellent — matching bias, ~9x faster. The full grid test told a different story: consistently worse bias than the current alternating scheme in most cells, and one badly broken cell (S/N=60, σ=150: 8 of 15 fits failed, vs. 0 for the current scheme).

Likely cause: the multi-start pool for this experiment was seeded from a single arbitrary template rather than a sensible initial mixture, unlike the current scheme's per-iteration, better-informed restarts — a fixable implementation gap, not necessarily proof the underlying technique is unsound. As tested, though, it made things worse, not better — the small-sample smoke test was misleading, a recurring lesson in this project. Not adopted; not worth pursuing further without a specific, motivated reason to revisit the multi-start design.

17Log-wavelength considered, not adopted

Most spectral-fitting codes in this field (pPXF included) work in log-wavelength, since a Doppler shift is multiplicative in λ and only becomes a fixed, translation-invariant shift after taking a log — the coordinate system where the LOSVD convolution is a literal, FFT-friendly convolution. This package does not do that: forward_model.shift_template applies the exact division λ_rest = λ_obs/(1+v/c) per pixel, directly on the native linear-Å grid, via direct interpolation rather than a shift-invariant shortcut.

Direct profiling settled whether switching would help: building the template stack (the part log-λ+FFT would speed up) is 23.6 ms, versus 6985 ms for the optimization itself — 0.3% of total fit time. Switching would not deliver a measurable speedup at current problem sizes, and would be a large, invasive rewrite (LSF matching, the continuum spline, and the entire test suite's mock generation all currently assume a linear grid). The current exact per-pixel approach is mathematically correct regardless of grid spacing — there is no correctness defect from staying in linear-λ, only a small, already-quantified effective-resolution variation (~4-5%) across a wide fit window. Documented as the right fix if E-MILES-scale template counts (hundreds of SSPs, §15) ever make template-stack construction a measurable fraction of cost — not a currently justified change.

18Known limitations

  • h3 recovery is severely suppressed at low-to-moderate σ for genuinely nonzero true h3 — stays near zero (full suppression) across σ = 20-80, only starting to recover above σ ≈ 140. No calibration data exists yet to correct this.
  • σ ≈ 300 km/s has an unresolved "sloppy manifold" over-coverage issue — bootstrap intervals become measurably too wide as S/N improves, the opposite of the naive expectation.
  • Fixed regularization is still the default (§8) — adaptive selection is validated but not yet promoted, pending the firming-up run and the calibration coupling in §14.
  • E-MILES integration is not production-ready (§15) — viable in the validated narrow window with continuum-cofitting on, not yet wired into the standard template-loading path.
  • shape_aware_correction (a separate, self-referential geometric correction for the taper's own windowing bias) is real and validated for skewed/kurtotic truth, but measurably worsens σ above σ ≈ 300 — off by default, opt-in only.
  • One shared LOSVD and one shared continuum across all templates — no per-population kinematics (a grouped-component extension has been discussed at length but not built) and no per-template continuum.
  • Noise covariance is a single scalar ρ (AR(1)), not a measured kernel shape — deliberately the simplest model that could be right, not yet stress-tested outside the calibration regime it was measured in.
